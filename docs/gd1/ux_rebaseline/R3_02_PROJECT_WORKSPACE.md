# R3.2 — Project Workspace & real P/S/T actions

## Scope

- R3.1 Recent Stores remains authoritative for explicit store selection. Before an existing SQLite store is successfully loaded, the central workspace displays the R3.1 store chooser. After successful load, the R3.2 dashboard replaces the chooser; **Đổi kho** returns to R3.1 without closing, migrating or creating SQLite.
- The dashboard presents one project selector, counts and distinct tabular listings for Specimens, Sessions, Captures and ProcessingRuns. These are all derived from `ProjectLoadBundle.trees`, the same immutable DTOs as Explorer. No fake records or background DB reads are generated by widgets.
- A dashboard row is a `SelectionRef`; it selects the corresponding Explorer entry, which remains the single selection authority and drives the Inspector. The main work area is an overview/table, not a duplicate nested tree.
- The `+ Tạo dự án`, `+ Thêm vật mẫu`, `+ Tạo phiên quét` buttons call pre-existing 07.5 `_create_*` flows, including validation, confirmation, write worker, code assignment, post-write reload and pending numbering recovery. UI permissions are inherited from `_can_write_project()`: v1 is read-only; v2 is writable when no other worker is busy. The targeted parent must be selected via Explorer/central table.
- Distinct 1px Qt separator widgets between header, project context and tabular content; white content, restrained cobalt accents, no painted line crossing text; no new dock, no shell changes. Existing scroll host, legacy objectName and hidden welcome card remain for 06–08 test compatibility.

## Deferred

- Metadata editing/close/RAW verification continue from pre-existing Inspector (R3.3 expands it). Create *data store* wizard is not part of R3.2 and cannot be emulated by opening a folder. ProcessingRun overview is read-only; R3.4 provides its own workspace.
- The dashboard never asserts filesystem materialization or verified RAW simply from a code or output reference. `Chưa cấp mã` remains visible for legacy records.

## Acceptance

1. Empty launch: SQLite untouched, recent chooser visible, dashboard hidden.
2. v1 store: read-only Project overview; v2 store: real Project/Specimen/Session linked CRUD through 07.5 service; no fake numbers.
3. Central Project selection and row selection synchronize with Explorer and Inspector, preserving project lineage.
4. Busy state disables writes, errors do not retain stale dashboard, reload after a write yields new actual DTO.
5. Header/context/content separated visibly; Project workspace remains usable with Explorer/Inspector/Task Dock on a 1366×768 Windows viewport and maximized desktop. Verify 100/125/150% DPI where available.
6. All existing architecture, Qt, SQLite, RAW and native smoke regression remains green. Two historical Windows symlink skips are tracked separately.
